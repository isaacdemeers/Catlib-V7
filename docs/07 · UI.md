
# 07 · UI Builder (menus and buttons)

> **Goal:** create buttons and interface elements with **a single block**, with entrance animation, hover, click, sounds, and display depending on the scene.

⬅️ [Cursor](<06 · Cursor.md>) · [Index](../README.md) · ➡️ [Text](<08 · Text.md>)

---

## 1. The principle

The **`ᗢ UI`** sprite makes interface elements. You describe an element with the **`〉UI new`** block: where it goes, what size, which images to use, on which scenes it's visible. Catlib creates the clone, handles hover and click, and **deletes the element by itself** when the scene is no longer the right one.

> [!IMPORTANT]
> `〉UI new` is defined **in the `ᗢ UI` sprite**. So you write your menu scripts **in `ᗢ UI`** (or in a copy of that sprite). The costumes and sounds used (`Icon_IDLE`, `HOVER`, `CLICK`…) must also be in that sprite.

## 2. The `〉UI new` block

```text
〉UI new / name [NAME] / xy [X] [Y] start offset [OX] [OY] / size [SIZE] size offset [OSIZE]
        / visible on scene [VSCENE] OR hide on scene [HSCENE]
        / idle sprite [IDLESPRITE] hover sprite [HOVERSPRITE] click sprite [CLICKSPRITE]
        / hover sfx [HOVERSFX] click sfx [CLICK sfx]
        / type [TYPE] action [ACTION] value [VALUE]
```

| Input | Role |
|---|---|
| `name` | A **name** to recognize the element (e.g. `play`). Found again in `〉UI name`. |
| `xy` | **Final** position. |
| `start offset` | **Starting** offset: the element starts at `(X + OX ; Y + OY)` then bounces to `(X ; Y)`. Gives an entrance animation. |
| `size` / `size offset` | Final size, and size offset at start ("pop" animation). |
| `visible on scene` | Scene(s) where the element **exists** (e.g. `MENU`). |
| `hide on scene` | The opposite: scene(s) where it **disappears**. |
| `idle sprite` | **Normal** costume. |
| `hover sprite` | Costume when the mouse **hovers**. |
| `click sprite` | Costume when **clicked**. |
| `hover sfx`, `click sfx` | **Sound names** (in the UI sprite) played on hover and click. |
| `type` | `BUTTON` for a **clickable** element. Any other value or empty: decorative element (not clickable). |
| `action`, `value` | **Free texts** you choose, found again in `〉UI action` and `〉UI value` to know what to do on click. |

Leave a slot **empty** to ignore the option (for example no sound).

### Visibility scenes

| You fill in… | Result |
|---|---|
| `visible on scene [MENU]` | The element exists as long as the scene is `MENU` (it disappears when the scene changes). |
| `visible on scene [MENU OPTIONS]` | Exists in `MENU` **and** `OPTIONS` (the name is searched as text inside the list). |
| `hide on scene [GAME]` | Exists everywhere **except** when the scene is `GAME`. |
| both empty | Always visible. |

> [!WARNING]
> The comparison searches for the scene name **inside** the typed text. So avoid scene names that contain each other (for example `GAME` and `GAME2`): `GAME` would also be recognized inside `GAME2`. Don't use the `!` character in a scene name (it's used internally for `hide on scene`).

## 3. A button's states

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Hover: cursor touches the button
    Hover --> Click: mouse button pressed
    Click --> Hover: button released
    Hover --> Idle: cursor leaves
```

During each state, the matching costume is shown, and the associated sound is played once on entering the state.

## 4. The 9 UI events

These are blocks in `ᗢ UI` that you **fill in** to customize behavior. They're called **for each element** (each clone).

| Block | When | Default content |
|---|---|---|
| `〉UI on create` | Once, at creation. | empty |
| `〉UI always` | **Every frame**, always. | the element bounces to its final position and size |
| `〉UI idle` | Every frame, at rest. | empty |
| `〉UI on hover` | Once, at the start of the hover. | empty |
| `〉UI while hover` | Every frame during the hover. | grows to 31 (bounce effect) |
| `〉UI on click` | Once, on click. | **empty: this is where you act** |
| `〉UI while click` | Every frame during the click. | shrinks to 28 (bounce effect) |
| `〉UI delete` | When the element must disappear. | deletes the element |
| `〉SELF on tick` | Every frame (rendering). | stamp + update |

### Knowing which element was clicked

In these blocks, you have the variables of the **current element**:

| Variable | Contains |
|---|---|
| `〉UI name` | The `name` given to `〉UI new`. |
| `〉UI type` | The `type`. |
| `〉UI action` | The `action`. |
| `〉UI value` | The `value`. |
| `〉UI scenes` | The visibility scenes text. |

## 5. Full example: a "PLAY" button

1. In `ᗢ UI`, add costumes `PLAY_IDLE`, `PLAY_HOVER`, `PLAY_CLICK` (and keep the sounds `HOVER`, `CLICK`).
2. Create the element at the right time:

```text
when I receive [SCENE MENU]
〉UI new / name [play] / xy [0] [-40] start offset [0] [-80] / size [30] size offset [-20]
    / visible on scene [MENU] OR hide on scene []
    / idle sprite [PLAY_IDLE] hover sprite [PLAY_HOVER] click sprite [PLAY_CLICK]
    / hover sfx [HOVER] click sfx [CLICK]
    / type [BUTTON] action [SCENE] value [GAME]
```

3. React to the click:

```text
DEFINE 〉UI on click
    if < 〉UI action = [SCENE] > then
        〉CMD / name [FADE] option [〉UI value] args [20 20] [] [] awaited? [NO]
```

The button slides in and grows, reacts to hover, plays its sounds, starts a **fade** to the `GAME` scene, then disappears by itself (because the scene is no longer `MENU`).

> [!TIP]
> `action` and `value` are **your own** texts. Here `SCENE` + `GAME` means "change scene to GAME"; you can invent `QUIT`, `VOLUME`, `LINK`… and handle each case in `〉UI on click`.

## 6. How it works internally (for the curious)

- `〉UI new` generates an **identifier** `UI.<number>` and stores all options in the `ᗢ DATA cache` list under names like `UI.123.NAME`, `UI.123.X`, `UI.123.HOVERSPRITE`… (see [chapter 11](<11 · Data and Save Files.md>)).
- The created clone re-reads these values at startup (`ᗢ CORE setup`).
- A clone is "hovered" when it touches the `ᗢ Cursor` sprite. Only one button can be hovered at a time (`〉CURSOR hovering ?`).
- When the element is deleted, its data is erased (`ᗢ CORE clear ui data`).

> [!NOTE]
> A click is detected even if you pressed the mouse **before** reaching the button: it's the combination "hovered + `〉CURSOR clicked ?` = `YES`" that counts.

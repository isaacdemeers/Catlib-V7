# 07 · UI Builder (menus et boutons)

> **Objectif :** créer des boutons et des éléments d'interface en **un seul bloc**, avec animation d'apparition, survol, clic, sons, et affichage selon la scène.

⬅️ [Curseur](06-curseur.md) · [Sommaire](../README.md) · ➡️ [Texte](08-texte.md)

---

## 1. Le principe

Le sprite **`ᗢ UI`** fabrique des éléments d'interface. Tu décris un élément avec le bloc **`〉UI new`** : où il va, à quelle taille, quelles images utiliser, sur quelles scènes il est visible. Catlib crée le clone, gère le survol et le clic, et **supprime l'élément tout seul** quand la scène n'est plus la bonne.

> [!IMPORTANT]
> `〉UI new` est défini **dans le sprite `ᗢ UI`**. Tu écris donc tes scripts de menu **dans `ᗢ UI`** (ou dans une copie de ce sprite). Les costumes et sons utilisés (`Icon_IDLE`, `HOVER`, `CLICK`…) doivent aussi être dans ce sprite.

## 2. Le bloc `〉UI new`

```text
〉UI new / name [NAME] / xy [X] [Y] start offset [OX] [OY] / size [SIZE] size offset [OSIZE]
        / visible on scene [VSCENE] OR hide on scene [HSCENE]
        / idle sprite [IDLESPRITE] hover sprite [HOVERSPRITE] click sprite [CLICKSPRITE]
        / hover sfx [HOVERSFX] click sfx [CLICK sfx]
        / type [TYPE] action [ACTION] value [VALUE]
```

| Entrée | Rôle |
|---|---|
| `name` | Un **nom** pour reconnaître l'élément (ex. `play`). Retrouvé dans `〉UI name`. |
| `xy` | Position **finale**. |
| `start offset` | Décalage de **départ** : l'élément commence à `(X + OX ; Y + OY)` puis rebondit jusqu'à `(X ; Y)`. Donne une animation d'entrée. |
| `size` / `size offset` | Taille finale, et décalage de taille au départ (animation de « pop »). |
| `visible on scene` | Scène(s) où l'élément **existe** (ex. `MENU`). |
| `hide on scene` | Au contraire : scène(s) où il **disparaît**. |
| `idle sprite` | Costume **normal**. |
| `hover sprite` | Costume quand la souris **survole**. |
| `click sprite` | Costume quand on **clique**. |
| `hover sfx`, `click sfx` | **Noms de sons** (dans le sprite UI) joués au survol et au clic. |
| `type` | `BUTTON` pour un élément **cliquable**. Autre valeur ou vide : élément décoratif (non cliquable). |
| `action`, `value` | **Textes libres** que tu choisis, retrouvés dans `〉UI action` et `〉UI value` pour savoir quoi faire au clic. |

Laisse une case **vide** pour ignorer l'option (par exemple pas de son).

### Les scènes de visibilité

| Tu remplis… | Résultat |
|---|---|
| `visible on scene [MENU]` | L'élément existe tant que la scène est `MENU` (il disparaît quand la scène change). |
| `visible on scene [MENU OPTIONS]` | Existe dans `MENU` **et** `OPTIONS` (le nom est cherché comme du texte à l'intérieur de la liste). |
| `hide on scene [GAME]` | Existe partout **sauf** quand la scène est `GAME`. |
| les deux vides | Toujours visible. |

> [!WARNING]
> La comparaison cherche le nom de la scène **à l'intérieur** du texte saisi. Évite donc des noms de scènes qui se contiennent (par exemple `GAME` et `GAME2`) : `GAME` serait aussi reconnu dans `GAME2`. N'utilise pas le caractère `!` dans un nom de scène (il sert en interne pour `hide on scene`).

## 3. Les états d'un bouton

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Hover: le curseur touche le bouton
    Hover --> Click: bouton de souris enfoncé
    Click --> Hover: bouton relâché
    Hover --> Idle: le curseur part
```

Pendant chaque état, le costume correspondant est affiché, et le son associé est joué une fois à l'entrée dans l'état.

## 4. Les 9 événements de l'UI

Ce sont des blocs dans `ᗢ UI` que tu **remplis** pour personnaliser le comportement. Ils sont appelés **pour chaque élément** (chaque clone).

| Bloc | Quand | Contenu par défaut |
|---|---|---|
| `〉UI on create` | Une fois, à la création. | vide |
| `〉UI always` | **Chaque image**, toujours. | l'élément rebondit vers sa position et sa taille finales |
| `〉UI idle` | Chaque image, au repos. | vide |
| `〉UI on hover` | Une fois, au début du survol. | vide |
| `〉UI while hover` | Chaque image pendant le survol. | grossit à 31 (effet rebond) |
| `〉UI on click` | Une fois, au clic. | **vide : c'est là que tu agis** |
| `〉UI while click` | Chaque image pendant le clic. | rétrécit à 28 (effet rebond) |
| `〉UI delete` | Quand l'élément doit disparaître. | supprime l'élément |
| `〉SELF on tick` | Chaque image (rendu). | tampon + mise à jour |

### Savoir quel élément a été cliqué

Dans ces blocs, tu disposes des variables de **l'élément en cours** :

| Variable | Contient |
|---|---|
| `〉UI name` | Le `name` donné à `〉UI new`. |
| `〉UI type` | Le `type`. |
| `〉UI action` | L'`action`. |
| `〉UI value` | La `value`. |
| `〉UI scenes` | Le texte des scènes de visibilité. |

## 5. Exemple complet : un bouton « JOUER »

1. Dans `ᗢ UI`, ajoute des costumes `PLAY_IDLE`, `PLAY_HOVER`, `PLAY_CLICK` (et garde les sons `HOVER`, `CLICK`).
2. Crée l'élément au bon moment :

```text
quand je reçois [SCENE MENU]
〉UI new / name [play] / xy [0] [-40] start offset [0] [-80] / size [30] size offset [-20]
    / visible on scene [MENU] OR hide on scene []
    / idle sprite [PLAY_IDLE] hover sprite [PLAY_HOVER] click sprite [PLAY_CLICK]
    / hover sfx [HOVER] click sfx [CLICK]
    / type [BUTTON] action [SCENE] value [GAME]
```

3. Réagis au clic :

```text
DEFINE 〉UI on click
    si < 〉UI action = [SCENE] > alors
        〉CMD / name [FADE] option [〉UI value] args [20 20] [] [] awaited? [NO]
```

Le bouton arrive en glissant et en grossissant, réagit au survol, joue ses sons, lance un **fondu** vers la scène `GAME`, puis disparaît tout seul (car la scène n'est plus `MENU`).

> [!TIP]
> `action` et `value` sont des textes **à toi**. Ici `SCENE` + `GAME` veut dire « change de scène vers GAME » ; tu peux inventer `QUIT`, `VOLUME`, `LINK`… et gérer chaque cas dans `〉UI on click`.

## 6. Comment ça marche en interne (pour les curieux)

- `〉UI new` génère un **identifiant** `UI.<nombre>` et range toutes les options dans la liste `ᗢ DATA cache` sous des noms comme `UI.123.NAME`, `UI.123.X`, `UI.123.HOVERSPRITE`… (voir [chapitre 11](11-donnees-sauvegardes.md)).
- Le clone créé relit ces valeurs au démarrage (`ᗢ CORE setup`).
- Un clone est « survolé » quand il touche le sprite `ᗢ Cursor`. Un seul bouton peut être survolé à la fois (`〉CURSOR hovering ?`).
- Quand l'élément est supprimé, ses données sont effacées (`ᗢ CORE clear ui data`).

> [!NOTE]
> Un clic est détecté même si tu as enfoncé la souris **avant** d'arriver sur le bouton : c'est la combinaison « survolé + `〉CURSOR clicked ?` = `YES` » qui compte.
